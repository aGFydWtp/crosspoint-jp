# Architecture Decision Records

このフォーク固有の設計判断を、判断した時点の根拠つきで残す場所。

「なぜこうなっているのか」がコードやコミットメッセージから読み取れない
判断、とくに**後から見て不合理に見えるが当時は理由があった**ものを対象に
する。将来その判断を覆すときに、何を確認すべきかが分かる状態を目指す。

## 書き方

決まった形式はないが、少なくとも以下を含める。

- **背景** — 何が問題だったか。数値や実測値があれば書く
- **選択肢** — 検討した案とそれぞれの利点・欠点。採用しなかった案こそ重要
- **決定** — 何を選んだか、なぜか
- **将来見直すときの判断材料** — どうなったら覆すべきか、覆す前に何を
  確認すべきか。ADR の価値はほぼここにある
- **影響** — 副作用、他プロジェクトや本家との関係

ステータスは `採用` / `再検討中` / `破棄 (ADR-XXXX で置き換え)` を使う。
判断が覆ったら、元の ADR を書き換えるのではなくステータスを更新し、
新しい ADR を追加する。
